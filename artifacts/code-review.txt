代码审查摘要
============

原实现的问题：无更新监测；安装目录遗漏卸载注册表；整包读入内存；
直接覆盖写入；仅凭 3.0x 字符串判断补丁；在整个头部替换哈希，遇到
重复哈希会拒绝；回滚未确认当前包版本；手工入口未正确保留退出码。

当前实现：
1. 当前用户登录自动任务与独立安装的运行目录，支持同名覆盖及新文件名。
2. 属性变化与稳定窗口确认；正在使用或更新时延后；无变化不重复读包。
3. 流式读取头部和 core.js，原位替换菜单，保持其他字节与偏移。
4. 按 JSON 路径修改目标完整性字段；校验全部 core.js 分块；共享区域拒绝修改。
5. 候选包完整校验、原版快照、操作互斥锁、原子替换和写入后复查。
6. 回滚确认当前文件和快照的哈希；旧备份先重现补丁才能接纳。
7. 生命周期互斥、停止事件与锁内停止检查，防止关闭/回滚后的排队任务再补丁。
8. 任务归属检查；当前用户 Interactive 登录；日志与快照在源码外。
9. 所有入口采用完整 Windows PowerShell 路径并保留实际退出码。

边界：新客户端的菜单布局改变时拒绝补丁，需适配；自动维护在客户端
彻底退出及文件稳定后处理，已打开的客户端需要下一次打开才生效。
